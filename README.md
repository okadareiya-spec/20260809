# 会議室予約 LINE Bot

社内の会議室12室を LINE から予約するシステム。Google Apps Script とスプレッドシートで構成し、
共有カレンダーとメール（`.ics` 添付）で個人のカレンダーへ連携する。

**このリポジトリは非公開で運用すること。** ドキュメントには認証方式の詳細と、
その方式で受容したリスクの評価が含まれる。

## 構成

| ディレクトリ | 内容 |
|---|---|
| `src/` | Apps Script のソース。`clasp` で GAS プロジェクトと同期する |
| `docs/` | 要件定義・技術仕様・稼働手順・利用ガイド・検証報告書 |
| `tools/` | リッチメニューの生成・登録、ガイドと報告書の生成スクリプト |

## ソースの構成

| 接頭辞 | 役割 |
|---|---|
| `lib_*` | シートアクセスと日時の共通基盤 |
| `core_*` | 空き判定・予約の書き込み・カレンダー同期・通知・シート編集の取り込み |
| `flow_*` | LINE の会話フロー。**イベントを受けてメッセージ配列を返す純粋関数**とし、送信と分離してある |
| `line_*` | Messaging API のラッパーと、postback・入力待ち状態の扱い |
| `main.js` | Webhook の受信 |
| `test_*` / `selfcheck.js` | 検証。エディタから実行する |

会話フローを送信から分離しているのは、**LINE を介さずに会話全体をテストするため**である。

## 開発

```bash
npm install -g @google/clasp
clasp login
clasp push --force
```

**コードを変更したら、必ずウェブアプリを再デプロイすること。** `/exec` はデプロイした時点の
バージョンを実行し続けるため、`clasp push` だけでは LINE 側の挙動は変わらない。
手順は `docs/04_稼働手順書.md` の STEP 4。

## 検証

エディタから実行する。すべて合格していることを確認してから変更をデプロイすること。

| 関数 | ファイル | 内容 |
|---|---|---|
| `selfCheck` | `selfcheck.js` | 構成・タイムゾーン・列書式・設定値の診断 |
| `testAvailability` | `test_availability.js` | 空き判定（45項目） |
| `testReservation` | `test_reservation.js` | 予約の書き込みと排他制御（31項目） |
| `testNotify` | `test_notify.js` | 通知文面と `.ics`（45項目） |
| `testLine` | `test_line.js` | 会話フロー全体（57項目） |
| `testAdminEdit` | `test_admin.js` | シート直接編集の取り込み（34項目） |

シートに書き込むテストは、目印を付けた行を `finally` で必ず削除する。

## 秘密情報の扱い

以下はリポジトリに含めない（`.gitignore` で除外済み）。

- `src/.env` — LINE のチャネルアクセストークン
- `.clasp.json` / `.clasprc.json` — GAS プロジェクトIDと認証情報

チャネルアクセストークン・Webhook トークン・共有カレンダーIDは、
**Apps Script のスクリプトプロパティに保存し、コードに書かないこと。**
コードに書くとデプロイのバージョン履歴に残り続ける。
